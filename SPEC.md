# Спецификация Delegirium (Делегириум) 0.1

Набросок языка. Версия зафиксирована в `Delegirium::VERSION` и в протоколе промпта
(`delegirium-prompt/1`), который входит в отпечаток кеша.

## 1. Идея

Delegirium — надмножество PHP с одной заменой: **тело функции можно не писать**.
Вместо блока операторов ставится маркер `ai;`, а тело генерирует модель по
контракту, выведенному из объявления.

Ключевое решение: генерация — часть **сборки**, а не рантайма.

1. Компилятор читает `.dlr`, находит AI-объявления и строит для каждого промпт.
2. Провайдер возвращает операторы тела.
3. Тело проверяется валидатором; при ошибке модель получает её текст и пробует снова.
4. Проверенное тело кешируется под отпечатком промпта и вклеивается в исходник.
5. Итоговый файл проверяется парсером PHP — на выходе всегда валидный PHP.

Причины: предсказуемая стоимость, отсутствие сетевых задержек в проде, возможность
ревью сгенерированного кода глазами, воспроизводимость сборок.

## 2. Синтаксис

### 2.1. Объявление с AI-телом

```
modifiers? 'function' name '(' params ')' (':' type)? 'ai' ';'
```

Примеры:

```php
public function add($x, $y): int ai;
static function parse(string $s): array ai;
function triple(int $n): int ai;
```

Правила:

- `ai` — зарезервированное слово **в позиции тела**. Оно допустимо как имя метода
  или как имя параметра (`function f($ai)`) и не является маркером вне этой позиции.
- После `ai` обязательна `;`. Блока `{ }` нет.
- Модификаторы, параметры по умолчанию, ссылки `&$x`, вариадические `...$rest`,
  `use`-списки для обычных функций, nullable/union/intersection-типы, атрибуты —
  всё, что PHP допускает в заголовке, допускается и здесь.
- Класс, интерфейс, trait, enum, namespace — обычные: маркер заменяет только тело.
- Код, не являющийся AI-объявлением, компилируется байт-в-байт.

Всё, что находится в докблоке объявления, — часть контракта и попадает в промпт.
Особый смысл имеют теги:

| Тег | Значение |
|---|---|
| `@pure` | запрещены I/O, время, случайность, глобальное состояние, `static`-переменные |
| `@throws E` | модель обязана бросать именно `E` в описанном случае |
| `@param` / `@return` | уточняют типы, если их нет в сигнатуре |

### 2.2. Рантайм-генерация (описано, не реализовано)

Маркер `ai runtime;` оставляет функцию без тела в сгенерированном PHP:

```php
public function add($x, $y): int ai runtime;
```

компилируется в

```php
public function add($x, $y): int
{
    return $this->__ai->call(__FUNCTION__, get_defined_vars());
}
```

Это режим для динамических случаев: результат мемоизируется по значениям
аргументов, а полученный код проходит тот же валидатор перед `eval` в изолированном
процессе. Именно эта форма соответствует примеру `return $this->ai->(__FUNCTION__);`.

## 3. Семантика

### 3.1. Контракт

Контракт функции — это `signature + returnType + docblock + @pure`. Других
источников истины нет. Контракт не должен быть двусмысленным: если модель может
истолковать поведение двумя способами, это дефект контракта, а не модели.

### 3.2. Отпечаток и кеш

```
key = SHA-256(protocol, provider, model, fqName, signature, returnType, doc, purity)
```

Свойства:

- **Идемпотентность.** При неизменном контракте и модели сборка берёт тело из кеша
  и не обращается к сети.
- **Инвалидация.** Любое изменение контракта или модели даёт новый ключ.
- **Обратная связь не входит в ключ.** Ретраи внутри одной генерации используют
  один и тот же ключ.
- **Кеш недоверенный.** Тело из кеша проходит валидацию так же, как свежее.

### 3.3. Валидация до исполнения

Проверки `Validator`:

1. Тело непустое, длиной до 4 КБ, без `<?php` и `?>`.
2. Сбалансированы фигурные скобки (тело не обрезано).
3. Нет запрещённых конструкций: `exec`, `shell_exec`, `system`, `passthru`,
   `proc_open`, `popen`, `eval`, `assert`, `include`/`require`, `$GLOBALS`,
   обратные кавычки, прямые операции с файловой системой и сетью.
4. Нет объявлений функций, классов и namespace внутри тела.
5. Для `@pure`: нет `echo`/`print`, `static`-переменных, вызовов `time`, `rand`,
   `random_int`, `getenv`, `date` и подобных источников недетерминизма.
6. При объявленном типе возврата есть `return` или `throw`.
7. После вклейки **весь файл** разбирается парсером PHP (`token_get_all(TOKEN_PARSE)`).

Ошибка валидации — это не фатальный сбой, а prompt-фидбек: модель получает текст
ошибки и переписывает тело. Число попыток ограничено (`maxAttempts`, по умолчанию 2).

### 3.4. Типы и ошибки

Типы объявлений — это рантайм-гарантии PHP (`TypeError`), а не проверки компилятора.
Обязательства по исключениям (`@throws`) валидатор проверить не может — они
проверяются тестами и ревью. Это осознанное ограничение наброска: доказывать
поведение сгенерированного кода мы пока не умеем.

### 3.5. Чистота

`@pure` — единственная семантическая аннотация, влияющая на генерацию: она
попадает в промпт как жёсткое ограничение и проверяется валидатором. В будущем —
основа для мемоизации и параллельного исполнения.

### 3.6. Провайдеры

| Провайдер | Endpoint | Ключ | Модель по умолчанию |
|---|---|---|---|
| `openai` | `DELEGIRIUM_API_URL` или `https://api.openai.com/v1/chat/completions` | `DELEGIRIUM_API_KEY` | `gpt-4.1-mini` |
| `openrouter` | `DELEGIRIUM_OPENROUTER_URL` (базовый, по умолчанию `https://api.ru-openrouter.ru/v1`) + `/chat/completions` | `DELEGIRIUM_OPENROUTER_KEY` | `openai/gpt-4o-mini` |
| `recorded` | — | — | `fixtures/recorded.php` |

Модели OpenRouter задаются как `vendor/model`. Базовый URL нормализуется:
допустимы и `.../v1`, и полный `.../v1/chat/completions`. Для атрибуции уходят
заголовки `X-Title: Delegirium` и (если задан `DELEGIRIUM_OPENROUTER_REFERER`)
`HTTP-Referer`.

Приоритет выбора: явный `provider` в опциях или `--provider`, иначе
`DELEGIRIUM_PROVIDER`, иначе `auto` (ключ OpenRouter → `openrouter`, ключ OpenAI →
`openai`, без ключей → `recorded`). Провайдер и модель входят в отпечаток промпта,
поэтому смена модели инвалидирует кеш.

### 3.7. Конфигурация и `.env`

`Delegirium::boot()` (и `bin/delegirium`) читают `.env`, чтобы не требовать
ручного `export`:

- порядок поиска: `DELEGIRIUM_ENV_FILE`, иначе `.env` в корне проекта,
  затем `.env` в текущем каталоге;
- синтаксис: `KEY=VALUE`, `export KEY=VALUE`, комментарии `#`, значения в `""`
  (с `\n`, `\r`, `\t`, `\"`, `\\`) и в `''` (без раскрытия), inline-комментарий
  только после пробела, `KEY=` — пустое значение;
- приоритет: переменные из окружения (shell/CI) **не перезаписываются**;
  перезапись — только явно: `DotEnv::loadFile($file, overwrite: true)`;
- диагностика: `delegirium env` показывает прочитанные файлы и значения,
  ключи с `KEY`/`SECRET`/`TOKEN`/`PASSWORD` маскируются.

`.env` не коммитится (см. `.gitignore`), в репозитории лежит шаблон `.env.example`.

## 4. Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| `нет записанного тела для X` | оффлайн-провайдер без fixtures | запустить с `DELEGIRIUM_API_KEY` и `--record` |
| `openai`/`openrouter`, HTTP 401/404 | неверный ключ, модель или URL | проверить `DELEGIRIUM_*_KEY`, `DELEGIRIUM_*_MODEL`, `DELEGIRIUM_*_URL` |
| `openai`/`openrouter`, запрос не удался | нет сети, DNS или TLS | проверить прокси/файрвол и схему URL |
| переменная «не задана», хотя есть в `.env` | файл не там, или значение перекрыто shell | `delegirium env`; `DELEGIRIUM_ENV_FILE=/path/.env` |
| `тело пустое` / `нет return` | модель вернула не то | `--regen`; уточнить докблок |
| `сгенерированный код не компилируется` | модель выдала мусор | `--regen`, сменить модель, сузить контракт |
| `запрещённый вызов exec()` | модель решила «помочь» | исправить промпт/контракт, не отключать валидатор |

## 5. Что дальше

- `ai runtime;` — ленивая генерация с мемоизацией и изоляцией процесса.
- Генерация тестов из докблока и прогон их до вклейки тела (property-based check).
- `ai test;` — функция-оракул: тело пишет модель, а человек задаёт примеры
  в `@example`-тегах.
- Семантический кеш: переиспользование тел между похожими контрактами через
  эмбеддинги (с обязательной повторной валидацией).
- Песочница исполнения (seccomp/отдельный процесс) как системная гарантия вместо
  статических запретов.
- `delegirium.lock` — фиксация отпечатков и версий моделей для воспроизводимых сборок.
